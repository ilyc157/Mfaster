# 卡片版式规范

**只有一种卡片**：会话里直接渲染的单屏片段（`card.render_compact`）。

它只有一件事要干：让人在一屏之内决定「要不要下单」。所以是纵向单栏、一人一行、宽度跟容器走，
不折叠、不悬停、不依赖外部图片和字体。

改版式改 `scripts/card.py`，不要在对话里手写 HTML。

> 曾经有过一套「430px 长卡 + Chrome 截图发群」的版式，已经去掉。
> 原因：截图比渲染慢一个数量级，而且 Chrome 最小窗口 500 宽、截图 430 宽，右边必被切一次。

## 结构

```
┌ 麦当劳 · 拼单   麦乐送                     ¥146.50 ┐
│ 云栖花园 3 栋 502 · 宵夜 · 人均 ¥29.30 · 5 人 5 件 · 超预算 │
├────────────────────────────────────────────────────┤
│ 张子涵   高达吉士双牛堡                     ¥26.00  │
│          换 ①培根芝士双牛堡 +¥1.00 ②培根安格斯厚牛堡 +¥12.50
│ 王总     麦辣鸡腿汉堡                       ¥25.50  │
│          换 ①麦辣鸡腿汉堡套餐 +¥15.00          │
│ 同事A    畅享吃鸡三人餐 ×1  [3 人共用]      ¥28.67  │
│          脆汁鸡琵琶腿 · 中薯条 · 无糖可乐中杯        │
│          换 ①各点麦辣鸡腿堡三件套 +¥2.33            │
│ 同事B    与同事A共用「畅享吃鸡三人餐」      ¥28.67  │
│          换 ①各点板烧鸡腿堡三件套 +¥5.83            │
├────────────────────────────────────────────────────┤
│ 多人餐：畅享吃鸡三人餐 ×1 ¥86.00 · 3 人合买，省 ¥1.90│
│ 要改就说一句：「同事A 换第 2 个」「李四不要了」       │
└────────────────────────────────────────────────────┘
```

三条硬规矩：

1. **一人一行。** 这一行就是取餐时的发餐依据，不需要另做分餐表。
2. **砍掉理由、热量，但备选必须留。** 理由是解释过去，备选是决定未来。
   没有备选，「这个不行换另一个」就只能重新收单，等于把「调整快」废掉。
3. **只保留两个红字位置**：超预算、有待确认项的人名红点。其余一律黑灰。

字号基准是正文 18、标注 16。靠**减少内容**换单屏，不靠缩小字号。

## 三个分区

### 顶部（红底）

| 信息 | 要求 |
| --- | --- |
| 品牌 + 取餐方式 | 「麦当劳 · 拼单」+ 胶囊标签（麦乐送 / 到店自取） |
| 应付金额 | 30px，全卡最大的数字，只有这一个，右对齐 |
| 地点 | 外送写送达地址，到店写门店/会议室。**不写就是让人猜** |
| 餐段 | 宵夜 / 晚餐 / 午餐；有预约时间就带在后面 |
| 人均、人数件数 | 别让人自己算 |
| 超预算 | 只在超了才出现，带具体差额 |

### 中间（主体）

每人一行，三列：**名字（5.4em 定宽）· 吃什么（弹性）· 多少钱（右对齐）**。

- 商品名用菜单原名，不缩写；数量 >1 才标 `×N`。
- 套餐拆开写，跟在名字后面用 ` · ` 连起来，超过 4 项截断加 `…`。
  只写「三件套」等于没写——这是卡片存在的意义。
- 合买的多人餐：owner 那行标 `N 人共用`（黄底芯片），其他人那行写「与某某共用「X」」并显示分摊金额。分摊行不显示数量。
- 有待确认项的人，名字后面打一个红色 `·`，具体问题进底部 flags。

**备选行**（每人最多一行，跟在菜品下面）：

```
备选1 培根芝士双牛堡 +¥1.00　备选2 培根安格斯厚牛堡 +¥12.50
```

- 印的是「备选N」，不是「换 ①②③」——用户嘴上说「换成备选2」，卡上就得能对上这四个字。
- 编号 **必须和 `edit --swap "名字=N"` 的 N 一一对应**，从 1 开始、按 `alts` 数组顺序。
  卡片上换过一次编号，用户说「换成备选2」就会换错东西。
- 取的是这个人**第一项**（`items[0]`）的备选，与 `cli.py` 的 `--swap` 口径一致。多项的人只给第一项的备选。
- 差价三种写法：`+¥1.00` / `−¥10.00` / `同价`。符号比文字快。
- 最多三条，多了挤占单屏空间，而第三条以后基本不会被选。
- 合买的人也有备选：`备选1 各点麦辣鸡腿堡三件套 +¥2.33`，靠 `pre="各点"` 前缀说明这是拆开各点。
  合买是脚本替他做的决定，必须留一条退路。
- 没有备选的人**不占空行**——`_alt_line` 返回空字符串。

### 底部（浅米底）

- 多人餐合并结果：名字 ×份数、总价、几人合买、省了多少。
- 需要拍板的事（红字），最多两条。
- 都没有时写「本单没有需要拍板的事」——**空着会让人以为是漏了**。
- 最后一行给改单例子，全是真人话。

| 元素 | 字号 / 字重 | 颜色 |
| --- | --- | --- |
| 品牌 | 24 / 800 | 白（红底） |
| 应付金额 | 30 / 800 | 白（红底） |
| 姓名 | 19 / 700 | `#181818` |

| 套餐组成 | 16 / 400 | `#6A6A6A` |

一屏里出现三种以上强调色，就等于没有强调。

## 禁写清单

这些词一旦出现，卡片就从「能拍板」变成「广告」：

- 「营养均衡」「荤素搭配」「好吃实惠」「超值之选」「人气必点」
- 「为您精心搭配」「根据您的口味」
- 任何把推断写成用户原话的句子（「你说想吃辣」而用户没说）
- 没有来源的「约 XX 大卡」

`planner._why()` 只拼事实短语。卡片不再显示理由，但这些字段仍在存档里，
被追问「为什么给我配这个」时要用它回答。

## 改版式之后要跑什么

```bash
python3 tests/test_offline.py                                # 结构与文案断言
python3 scripts/cli.py plan --roster-text "..." --widget temp/c.html   # 出片段
```

改完看四处：**超预算时抬头会不会把金额挤掉**、**八个人加各自备选会不会长到需要滚**、
**长菜名会不会把金额列挤到换行**（`mc-who` 是定宽，`mc-dish` 必须 `min-width:0` 才能正常省略）、
**备选编号是否还和 `--swap` 对得上**（改渲染别动 `alts` 数组顺序）。
