# 参赛提交材料

> 用于活动报名 / WorkBuddy 专项奖励提交表单的文案，可直接复制。

## 一句话介绍

把群里零散的点餐报单，变成一张会话里一屏看完、每人扫到自己那行就能拍板的拼单确认卡——自带备选、一句话改单，确认后直接给支付链接。

## 作品说明

### 解决什么问题

一次给一群人点麦当劳，真正会返工的不是选汉堡，而是把七八条格式各异的群聊消息对齐成一份不会返工的清单：谁的那条对上了菜单、套餐里到底装了什么、谁的需求没被满足（售罄、忌口冲突、「10 块」是 10 盒还是 10 块装）、一共多少钱、有人想改时要不要重来一遍。

现有工具大多是「菜为主线」——推荐套餐、算营养、拼最优组合；这个作品是「**人为主线**」：每人在卡片上占一行，顶上给组织者看总数和待拍板事项，底下给改单入口。因为真实场景里决策权在七八个人手里，不在算法手里。唯一要保证的是：每个人扫到自己那条，能在一秒内说「行」或者「换成 X」。

### 使用方式

**1. 贴报单**：把群里的原话直接粘过来，不用整理格式。

```
@张三 板烧鸡腿堡套餐 x1，不太饿
李四：巨无霸 + 中薯 + 可乐
王五 麦辣鸡腿堡套餐，再来个1+1随心配
@赵六 随便
```

**2. 出卡**：一条命令完成找店、拉菜单、对齐菜名、拆套餐、核价、渲染，十几秒后在会话里直接渲染出一张一屏看完的卡片，附三句话结论（人数件数金额人均、谁的需求对上了、哪件事要拍板）。全程不问预算、不问口味，地址默认用账号里存的（只有一个就直接用，两三个才让你挑，选项里带堂食/到店取和手填）。

**3. 改单**：说人话就行——「张子涵换第 1 个，王总不要了」，2 秒出新卡，金额、人均、多人餐分摊全部跟着变。每人下面本来就挂着备选，不用重新描述需求。

**4. 下单**：明确确认后创建订单，直接给支付链接（手机点开就付）；卡片本身又是分餐单，取餐时一人一行照发，不用排队点名。

### 实现思路

核心判断是**不把不确定的活交给模型**。MCP 的 `query-meals` 一次返回两万多字，如果由模型逐条调用：上下文会被原始菜单塞满，后面每步都变慢；而菜单价是「元」、核价是「分」，套餐拆解要模型在文本里手算，必错；改一条需求还得重走全流程。

所以分工是：**脚本做确定性的事，模型做人才能做的事。**

```
用户粘贴群聊文本
  → 报单解析（本地规则：说话人 / 餐品 / 数量 / 备注 / 忌口 / 泛称）
  → 选地址与门店（账号地址优先；外送门店由地址决定）
  → 拉当前餐段菜单
  → 菜名对齐（口语 → 真实 SKU，对不上就标未满足并给最近替代）
  → 多人餐比价合并（只合并「随便」的人）
  → 拆套餐（主食 / 小食 / 饮品 + 每轮可换项与差价）
  → 一次性核价（金额只认 calculate-price，逐品小计摊到人）
  → 单屏卡片片段，直接在会话里渲染
  → 用户确认 → 下单 → 支付链接
```

一次完整点餐固定 4–6 次接口调用，人数不影响调用次数；菜单、门店、营养表走 5 分钟本地缓存，所以改单只需 1 次核价。模型上下文里只进脚本吐出的结论摘要（十来行），不进原始菜单。

### 亮点

1. **产物只有一个：会话内一屏卡片。** 不做长报告、不做图片。卡片只放决定要不要下单的信息——谁、吃什么、多少钱、能换成什么、哪件事要拍板；搭配理由和热量刻意不放（理由解释过去，热量没人看）。
2. **每人必须有备选。** 卡片上「备选1 X +¥1　备选2 Y +¥12.5」这一行是「调整快」的全部凭据，说「换第二个」就换，不用重新收单。合买的人也会留一条「各点 XX」的退路——那是脚本替他做的决定。
3. **多人餐自动合并，但有门槛。** 说「随便」的人 ≥2 时自动比价，更便宜才换，并在卡片底部写明「3 人合买，省 ¥1.90」；只合并「随便」的人（明确要牛肉堡的不参与），纯鸡翅桶不算一顿饭，省不到 ¥1 就不动。
4. **默认值兜住 90% 的追问。** 地址用账号里的、餐段按时钟自动切、预算口味不问。整个流程只会问两件事：账号里地址超过一个（选哪个）、账号里没地址（手填还是到店取）——因为地址选错的代价不是多花几块钱，是饭送到另一个区。
5. **不静默替换，把不确定摆在明面上。** 菜名对不上、售罄、忌口冲突，一律在人名后打红点、进底部 flags，并在对话里说清；「麦乐鸡 10 块」这类规格与数量的歧义会挂提醒让你拍板。
6. **对平台额度友好，也守住了钱。** 探索阶段只核价（免费），下单必须由用户明确选中「下单」；下单后把支付链接落盘，要再给一次链接就读文件，绝不重复下单再扣一次钱。
7. **零第三方依赖。** 纯 Python 3 标准库实现 MCP 客户端（含混合文本解包、错误码归因、只读缓存），`pip install` 都不用；130 条离线断言不需要 Token、不联网即可跑通。

### 边界

- 只用麦当劳中国官方 MCP 的实时菜单与核价，不预置菜单、不猜价格。
- 营养数据来自官方营养表，表里没有就空着，不拿相似商品凑数；卡片本身不显示热量。
- 需求解析是确定性规则 + 对话确认，不是「猜你喜欢」。
- 不确认不下单。
